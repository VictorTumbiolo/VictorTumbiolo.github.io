Landing a Spacecraft with TD3

A Twin Delayed DDPG agent learns to touch down softly on the pad in LunarLanderContinuous-v3. The interesting part wasn't getting it to land. It was getting it to stop hovering, and the length of an episode turned out to be the lever.

The problem: soft landing

Learn a control policy that lands on a designated pad, uses fuel sparingly and doesn't crash. The action space is continuous, so the agent has to output precise thrust levels instead of choosing from a few engine commands. That is why a continuous-control actor-critic method like TD3 is a good fit. The task counts as solved when the average reward is at least 200 over 100 consecutive evaluation episodes.

Environment

EnvironmentLunarLanderContinuous-v3 (Gymnasium, Box2D physics)
Settingscontinuous=True, gravity=-10.0, enable_wind=False
State (8-dim)x and y position, x and y velocity, angle, angular velocity, left-leg contact (0/1), right-leg contact (0/1)
Action (2-dim)Each in [-1, 1]: main engine throttle and side thruster

Reward shaping

  • Positive reward for moving toward the pad and staying upright.
  • Reward for each leg that touches the ground.
  • A small penalty for firing the engines, so fuel use costs something.
  • A large penalty (−100) for crashing, and a bonus of about +100 for coming to rest.

The hovering problem

Staying in the air costs very little, so the agent can learn to dodge the −100 crash by hovering and never collect the +100 landing bonus. Episodes that end positive but under about 100 are usually this behavior. It was the main challenge in the project, and the episode-length experiment targets it directly.

What the experiments vary

  • Episode length

    Maximum steps per episode: 250, 500 or 1000. This is the experiment shown on this page.

  • Exploration noise

    Initial noise level, and whether it decays over training.

  • Actor learning rate

    1e-4 baseline against 5e-4 and 5e-5, alone and combined with 500-step episodes.

The algorithm: TD3

TD3 (Fujimoto et al., 2018) is an off-policy, model-free actor-critic method that improves on DDPG (Lillicrap et al., 2015) with three changes, all in TD3Agent.py.

  • Clipped double Q-learning

    Two critics are trained. The bootstrap target uses min(Q1_target, Q2_target), which reduces overestimation bias.

  • Delayed policy updates

    The critics update every step. The actor and the target networks update only every policy_delay = 2 critic steps.

  • Target policy smoothing

    Clipped Gaussian noise is added to the target actor's action when computing the target Q-value, so the policy can't exploit sharp spikes in the Q-function.

Around those three, the agent uses experience replay (capacity 1e6) with uniform random minibatches, and soft target updates for the actor and both critics: target = tau*param + (1-tau)*target.

The two losses

Critic target:  y = r + (1 - done) * gamma * min(Q1', Q2')(s', a')
Actor loss:     -Q1(s, actor(s)).mean()

Networks actor.py critic.py

Actor:   state (8)        -> 256 -> 256 -> 2   LayerNorm + LeakyReLU per hidden layer, tanh output scaled by max_action
Critic:  state + action (10) -> 256 -> 256 -> 1   same structure, state and action concatenated at the input

Design choices

  • A slower actor than critic (1e-4 against 1e-3) keeps the policy from chasing inaccurate early value estimates.
  • LayerNorm in the hidden layers is for training stability.
  • A 10k-step random warm-up fills the buffer with varied transitions before gradient updates start.
  • Saving the best 100-episode-average actor, not the last one, guards against late-training regressions.
  • Shortening the episode limit is used as a way to stop the agent from hovering forever.

Findings

  • Episode length mattered most. 1000 steps converges fastest but allows long hovers. 500 is the best trade-off, with no evaluation dips. 250 never learns to land and averages about 103.
  • Exploration noise mattered little. All three configurations converge to roughly the same level, so TD3 is fairly robust to noise on this task. Noise 0.2 learns fastest early but is noisier at the plateau, and noise 0.1 with decay learns slowest.
  • A higher actor learning rate helped. 5e-4 learns faster and reaches higher rewards. Combined with 500 steps it gave the most consistent evaluation, with no failures. The lower rates (1e-4 and 5e-5) track each other and show several dips.
  • Every configuration except 250 steps clears the 200 threshold on average.
  • Future work: compare against DDPG to see whether TD3's extra complexity is needed here.

What each file does

Core training code

TD3Agent.pyThe TD3Agent class: actor, twin critics, target networks, optimizers, select_action, soft_update and train (critic update, delayed actor update, target smoothing).
actor.pyThe Actor network.
critic.pyThe Critic network (Q-function).
replay_buffer.pyReplayBuffer: a preallocated circular numpy buffer with add and sample, which returns torch tensors on the device.
Driver.pyThe main training script. Builds the environment, agent and buffer, runs 1,500 episodes, logs rewards, saves the best actor, plots training, then loops forever rendering the best model.

Testing and visualization

100_consecutive_test.pyLoads a saved actor and runs 100 evaluation episodes without noise (up to 1000 steps each). Prints the rewards and final average, writes a log file and plots them.
display_model.pyLoads a saved actor and renders episodes live in a window, forever. T_MAX sets the steps per episode.
save_model_videos.pyRecords 25 consecutive episodes (T_MAX = 500) for each of three models and writes <model>_Playback.mp4 files. These are the videos on this page. Needs imageio and imageio-ffmpeg.

Data processing and plotting

One_File_Data_Processor.pyPlots one run's training rewards with a 100-episode moving average.
One_file_Evaluation_processor.pyPlots one run's 100 evaluation rewards.
data_conglomerator.pyOverlays the moving-average training curves of several runs from *_training_rewards.txt files in one directory.
evaluation_conglomerator.pyOverlays the evaluation curves of several runs from *_evaluation_rewards.txt files.

How they fit together

actor.py, critic.py, replay_buffer.py  ->  TD3Agent.py  ->  Driver.py
Driver.py  ->  training_rewards.txt, best_lander_actor.pth

best_lander_actor.pth  ->  100_consecutive_test.py  ->  evaluation_rewards.txt

  • Driver.py is the only script that trains.
  • The three testing and visualization scripts need only actor.py and a saved .pth file.
  • The plotting scripts read plain-text logs and never touch the models.

Running it

Setup

Python 3 with torch, gymnasium[box2d], numpy and matplotlib. The video script also needs imageio and imageio-ffmpeg.

pip install torch "gymnasium[box2d]" numpy matplotlib imageio imageio-ffmpeg

Train

  1. Open Driver.py and set directory_prefix to an existing output folder. The best model is saved to <directory_prefix>/best_lander_actor.pth.
  2. Uncomment the logging lines if you want the files. They are off by default so the script doesn't write files on its own.
  3. Run it. It trains for 1,500 episodes, shows the training plot (close it to continue), then renders the best model in an endless loop. Stop it with Ctrl+C.
python Driver.py

Evaluate over 100 episodes

In 100_consecutive_test.py, put a .pth path in the last line and real paths for the log file and the plot. It prints each reward and the average.

python 100_consecutive_test.py

Watch a model

Set MODEL_PATH in display_model.py. Episodes render in a window until you stop it.

python display_model.py

Save videos

Writes one mp4 per listed model into the current folder.

python save_model_videos.py

Make plots

For a single run, set the data path and output name in One_File_Data_Processor.py (training) or One_file_Evaluation_processor.py (evaluation). To compare runs, put files named <prefix>_training_rewards.txt or <prefix>_evaluation_rewards.txt in one folder, set data_directory and the output name in the matching conglomerator, and uncomment the color_map and parse_label block for your experiment.
